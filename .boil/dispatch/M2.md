## Design contract (build exactly this)

In `slim_llm_memory/rerank.py`, `Reranker.cross_encoder` and `_CrossEncoder` gain two knobs:

```python
@staticmethod
def cross_encoder(model: str = "BAAI/bge-reranker-v2-m3", *,
                  max_length: int = 256, batch_size: int = 32) -> "Reranker": ...
```

- `_CrossEncoder` stores both as public attributes `self.max_length` and `self.batch_size`
  (the caller reads them; `Reranker.cross_encoder().max_length` must be `256` and
  `.batch_size` must be `32` with no arguments).
- `max_length` is passed to the `CrossEncoder(...)` constructor as the keyword `max_length`.
- `batch_size` is passed to `.predict(...)` as the keyword `batch_size`.
- `.predict` receives a list of `(query, text)` tuples in the same order as the input texts,
  and the returned scores keep that order.
- `score(query, [])` returns `[]` without constructing or calling the model.
- Both are keyword-only after the model name. The existing lazy-import behaviour, the
  `_MODELS` cache keyed by model name, and the `ImportError` message for the missing
  `[rerank]` extra all stay exactly as they are.
- Why 256: the default was the library's 512 and the cross-encoder costs about a second per
  candidate on this CPU; halving the window is the cheap half of "make reranking affordable".

Scope: `rerank.py` only. Do not touch `topics.py`, `libraries.py`, or anything under `tests/`.
