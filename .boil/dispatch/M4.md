## Design contract (build exactly this)

Give `Library.ask` in `slim_llm_memory/libraries.py` the same adaptive policy `Topic.ask`
already has (read `Topic.ask` first and mirror it — do not invent a second policy).

Signature change — one new keyword argument:

```python
def ask(self, prompt: str, k: int = 5, *, topics=None, include_archived: bool = False,
        min_score: float = 0.3, max_words: int = 600, route="auto", mode: str = "hybrid",
        rerank: "bool | str | Reranker | None" = None,
        rerank_margin: "float | None" = None,
        entity: "str | None" = None) -> Result: ...
```

Behaviour:
- The decision is made **once, over the merged candidate pool of all scanned topics**, in
  `Library._merge`: fuse across topics as today, then
  `should_rerank([score for _, score in ranked], rerank_margin)` when `rerank_margin` is a
  float and a reranker is present. That keeps a query that is decisive library-wide from
  paying for a reranker call.
- Same three cases as `Topic.ask`: no reranker → no reranking; reranker without a margin →
  always; reranker with a margin → adaptive. `rerank="auto"` resolves to the default
  cross-encoder with `RERANK_MARGIN`.
- `Result.rerank_skipped` is set the same way, and is `True` only when a reranker was
  available and the policy declined it. When skipped, the returned hits are the merged
  fused top-k, no hit carries a `"rerank"` meta key, `reranked` is `None`.
- It must behave identically on both paths through `ask`: the routed path (`route=True`,
  which merges only the chosen topics) and the unrouted path. Note the existing
  `_scan_flat` fast path is only taken when `mode == "dense"` **and** no reranker and no
  entity filter — that condition must keep holding, so an adaptive request goes through
  `_merge`.

Scope: `libraries.py` only. `topics.py` and `rerank.py` are already done; do not change them.
Nothing under `tests/`.
