## Design contract (build exactly this)

Create `examples/04_rerank_bench.py`: what does the adaptive policy actually buy?

CLI:

    PYTHONPATH=. python examples/04_rerank_bench.py [--offline] [--json] [--margin FLOAT]

- default: a human table, one row per policy, columns `policy | mrr | hit@1 | rerank_calls | ms`
- `--json`: print **only** a JSON list of objects to stdout, nothing else, each with the keys
  `policy` (one of `"off"`, `"auto"`, `"always"`), `mrr` (float 0..1), `rerank_calls` (int),
  `ms` (float, median query latency). Extra keys are fine. Exit code 0.
- `--offline`: no network and no model download — `embedder="noop:64"` and a stub reranker
  (`Reranker.noop()` scores token overlap, which is deterministic and dependency-free).
  Without `--offline` use `ollama:nomic-embed-text` and `Reranker.cross_encoder()`.
- `--margin` overrides the adaptive margin (default `RERANK_MARGIN`).

The three policies, all over the same corpus and the same question set, using
`slim_llm_memory.evaluate`:

| policy | how |
|---|---|
| `off` | `ask(..., rerank=None)` |
| `auto` | `ask(..., rerank=<reranker>, rerank_margin=<margin>)` |
| `always` | `ask(..., rerank=<reranker>)` |

Count reranker calls by wrapping the reranker in a small counting subclass defined in the
script — do not add counting to the library.

The offline corpus and questions are yours to design, with two hard requirements that the
milestone is measured on:
1. `always` must make strictly more reranker calls than `auto` — i.e. at least one question
   in the set must have a decisive leader that the margin skips.
2. `auto`'s MRR must be greater than or equal to `off`'s MRR — the policy must not cost
   quality on the questions it does rerank.
Build a corpus where token overlap (what the noop reranker scores) genuinely identifies the
answer, so reranking helps rather than hurts; roughly 10-20 short documents and 6-10
questions is plenty. Use `min_score=0.0` so nothing is filtered out before the policy runs,
and pick `k` and the corpus so the pool has several plausible candidates.

Print a short header line to stderr (not stdout) in `--json` mode if you want progress output.

Scope: the new file under `examples/` only. The library is already finished — do not change
anything under `slim_llm_memory/`, and nothing under `tests/`.
