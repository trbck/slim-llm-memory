## Design contract (build exactly this)

Wire the (already existing) `should_rerank` decision into `Topic.ask` in
`slim_llm_memory/topics.py`.

Signature change — one new keyword argument, nothing else:

```python
def ask(self, prompt: str, k: int = 4, *, mode: str = "hybrid",
        rerank: "bool | str | Reranker | None" = None,
        rerank_margin: "float | None" = None,
        min_score: float = 0.3, max_words: int = 600,
        entity: "str | None" = None) -> Result: ...
```

Policy, exactly:
- `rerank` falsy/None → no reranking at all (today's behaviour).
- `rerank` truthy and `rerank_margin is None` → always rerank (today's behaviour).
- `rerank` truthy and `rerank_margin` is a float → **adaptive**: after fusion, call
  `should_rerank([score for _, score in ranked], rerank_margin)`. If it says False, skip the
  reranker entirely — the reranker object must not be called, not even with an empty list.
- `rerank="auto"` is sugar: resolve to the default cross-encoder and use `RERANK_MARGIN`
  when `rerank_margin` is None. Extend `slim_llm_memory.rerank.resolve` to accept the string
  `"auto"` (returning the default cross-encoder); every other unsupported value keeps raising
  `TypeError`.

Reporting on `Result` — one new attribute plus one repr change:
- `Result.rerank_skipped: bool`, default `False`. It is `True` only when a reranker was
  available and the adaptive policy declined to use it. It stays `False` when no reranker was
  asked for at all, and `False` when the reranker actually ran.
- When skipped: `Result.reranked` stays `None` and `rerank_ms` stays `0.0`, the hits are the
  fused top-k exactly as they would have been without any reranker, and no hit carries a
  `"rerank"` key in its meta.
- `repr(Result)` contains the literal text `rerank skipped` when `rerank_skipped` is True.
  Keep the existing `reranked (<name>) in <n> ms` fragment for the case where it ran.

Note the candidate pool: today `ask` fetches `pool = max(20, 4 * k)` candidates when a
reranker is present and `k` when not. Under the adaptive policy the pool is still fetched
(the decision needs the pool's score distribution), but when the decision is "skip" only the
top `k` are returned.

Scope: `topics.py` (`Topic.ask`, `Result`) and `rerank.py` (`resolve` accepting `"auto"`).
Do NOT change `Library.ask` — a later milestone does that. Nothing under `tests/`.
